Swift Market Intel — Chrome extension

Capture listings, prices, reviews and profiles from 12+ marketplaces in your browser and push them straight into your WorkflowSwift workspace.

Download the extension (.zip) Read the user guide

Current build — see below · Manifest V3 · Chrome / Chromium (any version that supports Manifest V3)

This is a sideload-only extension

Swift Market Intel is not published on the Chrome Web Store. There is no “Add to Chrome” button, Chrome will warn you that it came from outside the store, and it will not auto-update. Installing means unpacking the zip and loading it as an unpacked extension (step 1 below) — that is the only supported install path today. A one-click store listing is on the roadmap and will be announced on this page when it exists.

1. Install the extension (unpacked — the only supported path today)

Because the extension is sideload-only, installing it means Chrome's own developer path. This takes about a minute and is expected for the current build; it is not a workaround and it is not a sign that something is broken.

  1. Download the zip above and unpack it into a folder you will keep (e.g. ~/swift-market-intel). Do not delete the folder afterwards — Chrome loads the extension from it.
  2. Open chrome://extensions in Chrome (or any Chromium browser).
  3. Turn on Developer mode (top-right).
  4. Click Load unpacked and select the folder you unpacked (the one containing manifest.json).
  5. Pin Swift Market Intel to the toolbar. The popup header shows the version you are running — it must match the Current build shown at the top of this page.

2. Connect it to your WorkflowSwift account

  1. Right-click the extension icon → Options (or the Settings button in the popup).
  2. Create the token it asks for: open your WorkflowSwift app, click API Keys in the sidebar (or go straight to https://app.workflowswift.com/#api-keys), click + New API Key, give it a name such as Chrome extension, and copy the key — it is shown once and cannot be retrieved later.
  3. Paste that token into API Token.
  4. Leave API Base URL at its default (https://workflowswift.com/api/v1) unless you self-host.
  5. Click Test Connection. You should see Connected successfully! If you see Invalid API token, the token is wrong or was revoked; a 404 message means the base URL is missing its /v1 segment.
  6. Click Save. The token is stored in your browser only and is sent to WorkflowSwift, nowhere else.

3. Collect data

  1. Open a listing or profile on a supported platform.
  2. Click the extension icon, then Scrape Current Page. The extracted fields appear in the popup.
  3. Click Send to WorkflowSwift to push it into your account, where workflows and dashboard widgets can use it.

Permissions, plainly

This version requests no blanket access to every website. It asks for the supported marketplace domains above plus workflowswift.com, and for activeTab, which grants one-off access to the page in front of you only when you click the extension. You can check it yourself after installing: chrome://extensions → Details → Site access lists the individual domains, not “On all sites”. If you see a build asking for Read and change all your data on all websites, it is an older release — download the current build again and reload it.

Known limitations (current build)

  • Command acknowledgement is not yet available server-side, so commands sent from WorkflowSwift to a browser are delivered but never marked done.
  • Manual install means manual updates: re-download and replace the folder, then click Reload on chrome://extensions.

Troubleshooting

The popup says "Disconnected"

No token saved yet. Open Options and save one.

"Invalid API token" on Test Connection

The token was rejected (401). Re-copy it — tokens are shown only once when created.

Test Connection reports 404

The API Base URL lost its /v1. Reset it to https://workflowswift.com/api/v1. (Fixed in 1.2.0 — 1.1.0 shipped the wrong path and every call 404'd.)

Scraping returns nothing

Make sure the page is fully loaded and is one of the supported domains, then use Scrape Current Page from the popup.

Verify what you downloaded

The download button serves the current build from the WorkflowSwift app at /api/v1/extension.zip. To confirm the bytes you saved match what the server serves:

curl -s https://workflowswift.com/api/v1/extension.zip | sha256sum

The expected value is printed above and is also the one the Current build line at the top of this page shows. It is not written into this page by hand — it is read live from /extension-latest.json when the page loads, so it cannot go stale after a release.
